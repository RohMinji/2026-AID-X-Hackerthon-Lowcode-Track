# 해커톤 라이브 리더보드

스크린으로 생중계하는 실시간 스코어보드입니다. 화면은 `published.json`을
15초마다 폴링하고, 시간대에 따라 채점 대기 / 점수 공개 / 현황 공개 화면을
10초씩 자동으로 순환하며 보여줍니다 (아래 "화면 동작" 참고).

## 채점 결과(draft) vs 게시본(published) — 왜 파일이 두 개인가

채점 파이프라인은 매 회차 `result/result.json`(채점 결과)만 커밋합니다. 이 값이
화면에 **바로** 반영되지는 않습니다 — 진행자가 `admin.html`에서 순위를 미리
확인하고 공개 시각을 정해 **게시하기**를 눌러야 리더보드용으로 변환된 내용이
`published.json`(게시본)에 저장되고, 정한 시각에 실시간 화면(`index.html`)과
현황 화면(`status.html`)에 반영됩니다. 채점 도중 실수로 올라간 값이나 확정 전
점수가 관중 앞 화면에 바로 노출되는 것을 막기 위해서입니다.

```
채점 파이프라인 → result/result.json 커밋 (회차별 채점 결과)
                     │
                     ▼
              admin.html 에서 검토 (마지막 eval 기준 순위로 변환)
                     │  공개 시각 지정 → "게시하기"
                     ▼
              published.json 커밋 (게시본 + reveal_at + previous)
                     │  reveal_at 이 되면
        ┌────────────┴────────────┐
        ▼                         ▼
   index.html (실시간 화면)   status.html (현황 화면)
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 실시간 화면(스크린용) 페이지 구조 |
| `style.css` | 흰 배경 방송용 풀스크린 스타일 |
| `app.js` | `published.json` 폴링, 시간대별 모드 선택, 화면 자동 전환, 진행자 패널 로직 |
| `agents.json` | 에이전트 소개 화면 문구 (팀별 한 줄 소개·설명·핵심 기능) |
| `assets/` | 화면 배경용 유리 질감 이미지 |
| `admin.html` / `admin.js` | 관리자 페이지: 초안 미리보기, 게시, 순위 변동 리뷰 |
| `status.html` / `status.js` | 현황 화면: 게시된 전체 순위를 표로 상시 확인 |
| `draw.html` / `draw.js` / `draw.css` | 발표 순서 추첨(우주선 연출): 16팀 순서를 랜덤 결정 |
| `gacha.html` / `gacha.js` / `gacha.css` | 발표 순서 추첨(캡슐 뽑기 연출): 같은 목적, 다른 연출 |
| `dashboard.css` | 관리자/현황 화면 공통 스타일 |
| `shared.js` | 순위 계산·비교 로직 (세 화면이 공유) |
| `result/result.json` | 채점 파이프라인이 회차마다 커밋하는 채점 결과 (관리자 페이지가 읽음) |
| `result/samples/` | 1~8회차 채점 결과 샘플 (`result_1.json` ~ `result_8.json`) |
| `results.json` | 예전 형식의 샘플 결과 (지금은 발표 순서 추첨 화면만 사용) |
| `published.json` | 관리자가 게시한 결과 + 공개 시각(`reveal_at`) + 이전 점수(`previous`) |
| `history.json` | 게시할 때마다 쌓이는 스냅샷 기록 (감사/되돌아보기용) |

## `result/result.json` 형식 (채점 결과)

```jsonc
{
  "push_date": "20261008T09:32",   // 채점 시각 (한국 시간)
  "push_ID": 2,                    // 회차
  "push_results": {
    "eval_1": {                    // 1회차 결과: 16팀 전원
      "03b5f8b0-b214-49d7-a1a6-89c6772c6f6c": {   // appid (팀 고유 키)
        "agent_name": "Agent A",
        "agent_type": "agentic",   // agentic | workflow
        "total": 59.2,             // = common + custom + mission
        "common": 31.3,            // 최대 50
        "custom": 22.9,            // 최대 40
        "mission": 5.0             // 최대 10
      }
      // ... 16팀
    },
    "eval_2": { /* 2회차 결과: 16팀 전원 */ }
  }
}
```

- `eval_n`은 **n회차 채점**이고, 회차가 지날 때마다 하나씩 늘어납니다.
- 모든 `eval_n`에는 **16팀이 전부** 들어 있습니다. n회차에 채점을 신청하지
  않은 팀은 n-1회차 점수가 그대로 적힙니다. 팀별 신청은 최대 5번입니다.
- **순위는 마지막 `eval_n`의 `total` 기준**입니다(동점이면 이름순).
- 회차 간 순위 변동(▲▼)은 appid로 추적합니다.
- 항목별 만점(50/40/10)은 `shared.js`의 `EVAL_CRITERIA`에서 바꿀 수 있습니다.

## `published.json` 형식 (게시본)

관리자 페이지가 채점 결과를 아래 리더보드 형식으로 바꿔 저장합니다. 직접
만들 일은 없습니다.

```jsonc
{
  "event": { "name": "대회 이름", "updated_at": "2026-10-08T09:32:00+09:00", "round": 2, "push_id": 2 },
  "criteria": [ { "key": "common", "label": "공통", "max": 50 }, ... ],
  "teams": [
    { "appid": "03b5f8b0-...", "team": "Agent A", "agent": "Agent A", "agent_type": "agentic",
      "members": [], "total": 59.2, "scores": { "common": 31.3, "custom": 22.9, "mission": 5.0 } }
  ],
  "reveal_at": "2026-10-08T10:00:00+09:00",   // 이 시각부터 화면에 공개
  "previous": { /* 지금 화면에 나오는 이전 게시본, 같은 형식 */ }
}
```

- 예전 형식(`teams[].scores` 합계로 순위, `team` 이름으로 추적)도 그대로
  읽을 수 있습니다.

## 화면 동작 (시간대별 3가지 모드)

실시간 화면(`index.html`)은 흰 배경의 방송용 화면이며, **한 화면당 10초씩**
자동으로 넘어갑니다. 지금 몇 시인지와 `published.json`의 공개 시각
(`reveal_at`)을 보고 아래 세 모드 중 하나를 스스로 고릅니다.

| 모드 | 언제 | 화면 순서 |
|---|---|---|
| 채점 대기 | 매시 **40분부터 공개 시각까지** (공개 시각이 정각이 아니면 그 20분 전부터) | 1. 채점 중 → 2. `HH:MM 새로운 점수 공개 예정` + 남은 시간 |
| 점수 공개 | **공개 시각부터 30분 동안** | 0. 새로운 리더보드를 공개합니다! (`HH:MM 점수 기준`) → 1~3. 순위 변동 (16팀을 3화면으로, 낮은 순위부터) → 4. 라이징 스타 → 5. 다크호스 |
| 현황 공개 | 그 밖의 시간 | 1~3. 리더보드 (10–16위 → 4–9위 → TOP 3 시상대) → 4~6. 1·2·3위 에이전트 소개 (각각 한 화면) → 7. 4–7위 에이전트 소개 (한 화면) |

예: 13:00 공개라면 12:40~13:00 채점 대기 → 13:00~13:30 점수 공개 →
13:30~13:40 현황 공개 → 13:40부터 다시 채점 대기.

- **채점 대기 2번 화면의 시각**은 관리자가 게시할 때 정한 공개 시각입니다.
  아직 게시하지 않았으면 다음 정각이 표시됩니다.
- **순위 변동**: 이전 순위 → 현재 순위, ▲▼ 칸 수, 점수 증감(+/−)을 보여주고
  순위·점수 숫자가 이전 값에서 새 값으로 올라가는 애니메이션이 나옵니다.
- **라이징 스타**: 이전에 Top 7 밖이었다가 이번에 Top 7에 들어온 팀 중 점수가
  가장 많이 오른 팀(최대 3팀). 새로 진입한 팀이 없으면 Top 7 중 가장 많이 오른
  팀을 대신 보여줍니다.
- **다크호스**: 전체 팀 중 점수가 가장 많이 오른 팀(1위 크게 + 2·3위 작게).
- 라이징 스타·다크호스는 비교할 이전 점수가 있어야 나옵니다(첫 공개 때는 생략).
- 에이전트 소개 문구는 `agents.json`에서 읽습니다(아래 참고).
- 15초마다 `published.json`과 `agents.json`을 다시 불러옵니다. 모드 전환은
  화면을 띄운 PC의 시계 기준으로 정확히 그 시각에 일어납니다.
- 배경의 유리 질감 오브젝트는 `assets/` 폴더의 이미지입니다.

### 공개 전 점수는 어떻게 숨기나

관리자가 게시하면 `published.json`에 새 점수와 함께 `reveal_at`(공개 시각)과
`previous`(지금 화면에 나오는 이전 점수)가 같이 저장됩니다. 실시간 화면과
`status.html`은 `reveal_at` 전까지 `previous`를 보여주고, 그 시각이 지나면 새
점수로 바뀝니다. 그래서 정각 몇 분 전에 미리 게시해 둘 수 있습니다.
단, 정적 사이트라 `published.json` 파일 자체를 직접 열어보면 공개 전 점수도
보입니다(화면에 노출되지 않을 뿐입니다).

### 점수 공개 화면 미리보기

`index.html?demo`로 열면 `published.json`은 그대로 두고, 점수를 조금씩 깎은
가짜 "이전 점수"를 만들어 점수 공개 모드를 바로 보여줍니다. 리허설이나 디자인
확인용입니다. `index.html?mode=wait|reveal|status`로 특정 모드를 고정할 수도
있습니다.

## 팀 정보와 에이전트 소개 (`agents.json`)

```jsonc
{
  "agents": {
    "03b5f8b0-b214-49d7-a1a6-89c6772c6f6c": {   // result.json의 appid
      "agent_name": "Agent A",          // 알아보기 위한 메모 (화면에는 result.json 값 사용)
      "team": "팀 이름",                 // 비워 두면 agent_name이 팀 이름 자리에 표시됨
      "members": ["팀원1", "팀원2"],      // 비워 두면 agent_type(Agentic/Workflow) 표시
      "tagline": "한 줄 소개",
      "description": "두세 문장 설명 (1~3위 화면, 4~7위 카드에 표시)",
      "features": ["핵심 기능 1", "핵심 기능 2", "핵심 기능 3"]
    }
  }
}
```

화면은 이 파일을 15초마다 다시 읽으므로, 팀 이름·팀원·소개는 **다시 게시하지
않아도** 이 파일만 고쳐 커밋하면 바로 바뀝니다. 지금은 샘플 appid와 예시
문구가 들어 있으니, 실제 appid와 팀 정보로 바꿔 주세요. 소개가 없는 팀은
"에이전트 소개를 준비하고 있어요"로 표시됩니다.

## 진행자(호스트) 전용 숨김 패널

화면에는 버튼이 없고, 키보드 `P`를 누르면 진행자 패널이 열립니다. 관리자
페이지(`admin.html`)로 가는 링크는 이 화면 어디에도 없으니 주소를 직접 입력해
들어가세요.

- **화면 모드**: 자동(시간에 따라) / 채점 대기 / 점수 공개 / 현황 공개 중 강제 선택
- 이전/다음 화면, 자동 전환 일시정지/재생, 즉시 새로고침
- 현재 게시본의 공개 일정(대기 중/공개됨)과 불러오기 상태

단축키: `P` 패널 토글, `←/→` 화면 이동, `Space` 일시정지/재생.

## 관리자 페이지 (`admin.html`)

진행자가 결과를 검토하고 게시하는 페이지입니다. 정적 호스팅(GitHub Pages)에는
서버가 없으므로, 이 페이지는 브라우저에서 **GitHub API를 직접 호출**해
`published.json`을 커밋하는 방식으로 동작합니다.

1. 저장소에 대한 쓰기 권한이 있는 GitHub Personal Access Token을 준비합니다
   (fine-grained 토큰이면 이 저장소에 `Contents: Read and write` 권한만 부여).
2. `admin.html` 상단에 토큰을 입력하고 **저장**을 누릅니다. 토큰은 서버로
   전송되지 않고 브라우저 세션 저장소(`sessionStorage`)에만 남으며, 탭을
   닫으면 사라집니다.
3. `result/result.json`의 마지막 회차 기준 예상 순위표와, 지금 화면에 공개된
   점수 대비 변동(▲/▼/NEW)이 표로 보입니다. 몇 회차·몇 시 채점인지도 위에
   표시됩니다. "결과 JSON 직접 입력" 칸에는 항상 현재 `result/result.json`
   내용이 채워져 있습니다.
4. **점수 공개 시간**을 정합니다. 기본값은 다음 정각이고, "다음 정각으로" /
   "지금 바로" 버튼으로 빠르게 바꿀 수 있습니다. GitHub Pages 반영에 1~2분
   걸리므로 공개 시각보다 최소 3분 먼저 게시하세요.
5. **게시하기**를 누르면 확인창 후 `published.json`을 커밋합니다. 성공하면
   바로 아래에 "순위 변동" 리뷰(이전 점수 → 이후 점수, ▲/▼)가 나타나고,
   실시간 화면·현황 화면에는 정한 공개 시각에 반영됩니다(그 전까지는 이전
   점수가 그대로 보임). 공개 전에 다시 게시하면 앞선 게시본을 대체하고,
   비교 기준(이전 점수)은 그대로 유지됩니다. 동시에
   그 시점의 전체 순위 스냅샷이 `history.json`에 한 건 더 쌓입니다
   (아래 "게시 히스토리" 참고).

### `result.json`을 안 거치고 바로 붙여넣기

저장소에 아직 커밋되지 않은 채점 결과(슬랙/터미널 등으로만 받은 JSON)도 그대로
붙여넣어 미리보기·게시할 수 있습니다.

1. "결과 JSON 직접 입력" 칸의 내용을 지우고 채점 결과 JSON 전체를 붙여넣습니다
   (`result/result.json`과 같은 형식, 예전 리더보드 형식도 가능).
2. **이 내용 사용**을 누르면 형식을 검사하고, 통과하면 그 내용으로 아래
   미리보기 표(예상 순위·변동 배지)가 즉시 갱신됩니다. JSON이 깨져 있으면
   구체적인 오류 메시지가 뜨고 표는 바뀌지 않습니다.
3. 이후 **게시하기**를 누르면 저장소의 `result/result.json`이 아니라 지금
   붙여넣은 내용이 변환되어 `published.json`에 커밋됩니다.
4. **result.json 다시 불러오기**를 누르면 저장소의 최신 `result/result.json`
   내용으로 칸이 다시 채워지고, 붙여넣은 내용은 버려집니다.

### 게시 히스토리 (`history.json`)

게시할 때마다 그 시점의 전체 순위 스냅샷(시각, 이벤트 정보, 팀별 순위·점수)이
`history.json`의 `entries` 배열에 **추가**됩니다(기존 기록은 지우지 않고
계속 쌓입니다). 관리자 페이지 맨 아래 "게시 히스토리" 표에서 최근 게시
목록(시각·팀 수·1~3위)을 볼 수 있습니다. `published.json`을 커밋하는
요청과는 별도의 커밋으로 저장되며, 히스토리 저장에 실패해도(예: 네트워크
오류) 이미 끝난 게시 자체는 취소되지 않고 화면에 별도로 오류만 표시됩니다.

`admin.js` 상단의 `REPO_OWNER` / `REPO_NAME` / `BRANCH` 상수는 GitHub Pages
배포 워크플로우가 빌드하는 브랜치와 일치해야 합니다. 지금은 저장소가 처음에
비어 있어서 이 브랜치가 기본 브랜치가 됐기 때문에 `BRANCH`도 그 브랜치명으로
맞춰뒀습니다 — 나중에 `main`으로 정리되면 `admin.js`와
`.github/workflows/deploy-pages.yml`의 브랜치 설정을 함께 업데이트하세요.

이 페이지는 접근 자체를 막아두지 않았습니다(정적 사이트라 로그인 화면을 만들
수 없음). 실제 보안은 GitHub API가 담당합니다 — 쓰기 권한이 없는 토큰으로는
게시 요청 자체가 거부됩니다. `admin.html` 링크는 참가자에게 공유하지 마세요.

## 현황 화면 (`status.html`)

빔프로젝터의 순환 연출 없이, 게시된 전체 순위를 표 하나로 항상 볼 수 있는
화면입니다. 필요할 때 아무 때나 접속해서 확인하는 용도로, `published.json`을
15초마다 자동 갱신합니다.

## 발표 순서 추첨 (`draw.html`)

16팀의 발표 순서를 정하는 연출용 화면입니다. `results.json`에서 팀 목록(팀명·
에이전트명)만 읽어오고 점수는 사용하지 않습니다 — 점수 공개 전에 미리 써도
됩니다.

1. `draw.html`을 열면 우주선 16대가 지구 옆에 대기한 인트로 화면이 뜹니다.
2. **🚀 추첨 시작**을 누르면 각 우주선이 **서로 다른 무작위 시각**에 지구를
   출발합니다(동시 출발 아님) — 그래서 지금 화면에 보이는 위치만으로는
   "누가 잘 가고 있는지" 짐작할 수 없습니다. 출발한 우주선은 각자
   무작위 시간만큼 날다가 추진력을 잃고 멈추는데, 실제로 날아간 시간만큼
   지구에서 멀어진 자리에 그대로 정지합니다. 최종적으로 **지구에 가장
   가까이 멈춘 팀이 1번(첫 발표)**, 가장 멀리 멈춘 팀이 마지막 발표가
   됩니다.
3. 우주선이 멈출 때마다 오른쪽 "발표 순서" 패널에 팀 이름만 추가됩니다
   (번호는 아직 안 보임) — **16팀이 모두 멈추기 전까지는 누가 1등이고
   꼴찌인지 진행자를 포함해 아무도 알 수 없습니다.** 다 멈춘 뒤에야
   "🎉 추첨 완료!" 화면과 함께 1번부터 16번까지 전체 순서가 한 번에
   공개됩니다. **순서 복사**로 클립보드에 텍스트로 복사하거나, 화면을
   캡처해 두세요.
4. 다시 뽑아야 하면 **🔄 다시 추첨**(확인창 있음)으로 새로 진행할 수 있습니다.

순서를 결정하는 실제 난수는 우주선마다 "출발 지연 시각"(0~10초)과
"비행 시간"(4~18초)을 각각 무작위로 부여하는 것이고, 최종적으로 비행
시간이 짧은 순서대로 발표 번호가 매겨지므로 16개 순서의 모든 경우가
동일한 확률입니다. 출발 시각까지 무작위라서 화면만 보고 최종 순서를
예측하기 어렵습니다. 결과는 페이지를 새로고침하면 사라집니다(별도로
저장하지 않는 연출용 화면) — 필요하면 3번의 복사/캡처로 기록해두세요.

## 발표 순서 추첨 (`gacha.html`) — 캡슐 뽑기 버전

같은 목적(16팀 발표 순서 결정)을 다른 연출로 보여주는 화면입니다. 우주선
버전과 달리 이 화면은 **팀 이름을 전혀 표시하지 않고, 뽑을 때마다 번호만
보여줍니다** — 실제로 각 팀이 순서대로 나와서 기계를 직접 눌러 자기
번호를 뽑는 용도입니다. 그래서 `results.json` 같은 팀 명단도 필요 없는
완전히 독립적인 화면입니다.

1. `gacha.html`을 열면 1~16 번호가 든 캡슐 16개가 유리돔 안에서 둥둥
   떠 있습니다(어떤 캡슐에 어떤 번호가 들었는지는 보이지 않습니다).
2. 팀을 한 명씩(또는 정해둔 순서대로) 기계 앞에 세우고, **🎰 캡슐 뽑기**를
   누르게 하세요. 누를 때마다 무작위 캡슐 하나가 돔에서 사라지고, 트레이에
   떨어져 갈라지면서 **그 팀의 발표 번호**가 크게 드러납니다.
3. 오른쪽 "뽑힌 순서" 패널에는 몇 번째로 뽑았는지와 그때 나온 번호가
   쌓입니다(예: "1 → 7번", "2 → 3번"). 어떤 팀이 뽑았는지는 화면이 알지
   못하므로, 진행자가 직접 팀과 번호를 짝지어 기록해야 합니다.
4. 16번을 모두 뽑으면 "🎉 뽑기 완료!" 화면에 전체 뽑기 순서가 정리되어
   나타납니다. **순서 복사**로 클립보드에 복사하거나 화면을 캡처해 두세요.
5. 다시 뽑아야 하면 **🔄 다시 뽑기**(확인창 있음)로 돔을 다시 채우고
   새로 진행할 수 있습니다.

한 번 뽑힌 번호는 다시 나오지 않도록 뽑을 때마다 남은 목록에서 제거하는
방식(비복원추출)이라, 16번의 뽑기가 끝나면 1~16번이 정확히 한 번씩만
나옵니다. 애니메이션 도중에는 버튼이 잠겨서 연타로 두 번 연속 뽑히는 것을
막습니다. 이 화면도 결과를 저장하지 않으니 복사/캡처로 기록해두세요.

## 배포

`.github/workflows/deploy-pages.yml` 워크플로우가 `leaderboard/` 폴더 변경을 감지해
GitHub Pages로 자동 배포합니다. 저장소 Settings → Pages에서 Source를
**GitHub Actions**로 설정해야 합니다.
