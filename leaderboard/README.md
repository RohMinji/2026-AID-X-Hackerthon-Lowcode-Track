# 해커톤 라이브 리더보드

빔프로젝터로 생중계하는 실시간 스코어보드입니다. 화면은 `published.json`을
15초마다 폴링해서 자동으로 순위를 갱신하고, `TOP 3 시상대 화면`과
`4위 이하 순위 화면(여러 팀씩 분할)`을 자동으로 순환(auto-rotate)하며 보여줍니다.

## 초안(draft) vs 게시본(published) — 왜 파일이 두 개인가

채점 에이전트는 `results.json`(초안)만 커밋합니다. 이 값이 화면에 **바로**
반영되지는 않습니다 — 진행자가 `admin.html`에서 전체 순위를 미리 확인하고
**게시하기** 버튼을 눌러야 그 내용이 `published.json`(게시본)에 복사되고,
그제서야 실시간 화면(`index.html`)과 현황 화면(`status.html`)에 반영됩니다.
이렇게 분리해 둔 이유는 채점 도중 실수로 올라간 값이나 확정 전 점수가
관중 앞 화면에 바로 노출되는 것을 막기 위해서입니다.

```
채점 에이전트 → results.json 커밋 (초안)
                     │
                     ▼
              admin.html 에서 검토
                     │  "게시하기" 클릭
                     ▼
              published.json 커밋 (게시본)
                     │
        ┌────────────┴────────────┐
        ▼                         ▼
   index.html (실시간 화면)   status.html (현황 화면)
```

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 실시간 화면(빔프로젝터용) 페이지 구조 |
| `style.css` | 방송용 풀스크린 스코어보드 스타일 |
| `app.js` | `published.json` 폴링, 화면 자동 전환, 진행자 패널 로직 |
| `admin.html` / `admin.js` | 관리자 페이지: 초안 미리보기, 게시, 순위 변동 리뷰 |
| `status.html` / `status.js` | 현황 화면: 게시된 전체 순위를 표로 상시 확인 |
| `draw.html` / `draw.js` / `draw.css` | 발표 순서 추첨(우주선 연출): 16팀 순서를 랜덤 결정 |
| `gacha.html` / `gacha.js` / `gacha.css` | 발표 순서 추첨(캡슐 뽑기 연출): 같은 목적, 다른 연출 |
| `dashboard.css` | 관리자/현황 화면 공통 스타일 |
| `shared.js` | 순위 계산·비교 로직 (세 화면이 공유) |
| `results.json` | 채점 에이전트가 커밋하는 초안 결과 (샘플 포함) |
| `published.json` | 관리자가 게시한, 화면에 실제로 보여지는 결과 |
| `history.json` | 게시할 때마다 쌓이는 스냅샷 기록 (감사/되돌아보기용) |

## `results.json` / `published.json` 스키마

두 파일은 완전히 같은 스키마를 씁니다 (게시 = `results.json` 내용을
`published.json`으로 복사). 채점 에이전트는 `results.json`만 커밋하면 됩니다.
페이지는 같은 폴더에서 이 파일들을 직접 `fetch`하므로 별도 API 서버가
필요 없습니다.

```jsonc
{
  "event": {
    "name": "대회 이름",
    "updated_at": "2026-08-27T09:00:00+09:00", // ISO 8601, 화면 하단에 표시됨
    "note": "화면 상단에 표시할 짧은 안내 문구"
  },
  "criteria": [
    // 채점 항목 정의. 총점 = 모든 항목 max 합계
    { "key": "functionality", "label": "기능 완성도", "max": 30 },
    { "key": "technical", "label": "기술 구현", "max": 25 }
    // ...
  ],
  "teams": [
    {
      "team": "Team 01",           // 화면/정렬의 고유 식별자로 사용됨 (유일해야 함)
      "agent": "에이전트 이름",
      "members": ["팀원1", "팀원2"],
      "scores": { "functionality": 27, "technical": 22 }, // criteria.key와 동일한 키 사용
      "comment": "채점 코멘트 (현재 화면에는 노출하지 않음, 추후 확장용)",
      "submitted_at": "2026-08-27T08:40:00+09:00" // 동점자 타이브레이크(먼저 제출한 팀이 우선)에 사용
    }
  ]
}
```

- 순위는 `scores` 합계 내림차순 → 동점이면 `submitted_at`이 빠른 팀이 우선으로 계산됩니다.
- `team` 값은 회차 간 순위 변동(▲▼) 추적의 키이므로 중복 없이 고정된 값을 사용하세요.
- 팀 수는 16팀 기준으로 설계했지만, 팀 수가 달라져도 4위 이하 화면은 자동으로
  페이지를 나눠 표시합니다.

## 화면 동작

- 상단 표시줄: 대회명, LIVE 표시, 현재 시각, 안내 문구
- 메인 화면은 **최하위 순위 화면부터 시작해서 TOP 3 시상대로 끝나는 순서**로
  자동 전환(crossfade)됩니다. 16팀 기준이면 `10-16위 → 4-9위 → TOP 3` 순서이고,
  팀 수가 달라지면 4위 이하 구간이 자동으로 재분할되되 "낮은 순위 화면 먼저,
  시상대는 항상 마지막" 순서는 유지됩니다.
- 화면 전환 간격은 기본 8초이며, 하단 바에 `다음 화면까지 N초` 텍스트와
  줄어드는 진행 바로 남은 시간이 항상 표시됩니다.
- 순위가 오르면 초록, 내려가면 빨강으로 카드/행이 잠깐 빛나고, 점수가 오르면
  골드 링 애니메이션이 표시됩니다.
- 15초마다 `published.json`을 다시 fetch해서 최신 데이터로 갱신합니다
  (`results.json`이 아닙니다 — 게시 전에는 화면에 반영되지 않습니다).

## 진행자(호스트) 전용 숨김 패널

검색창/정렬 드롭다운 같은 관리용 UI는 화면에 노출되지 않습니다. 대신 화면
오른쪽 하단 구석에 거의 투명한 톱니바퀴(⚙) 버튼이 있고, 클릭하거나 키보드 `P`를
누르면 진행자 패널이 열립니다.

패널에서 가능한 것:
- 이전/다음 화면 수동 이동, 시상대로 바로 이동
- 자동 전환 일시정지/재생 (스페이스바로도 가능)
- 화면 전환 간격 조절 (4~30초)
- `published.json` 즉시 새로고침
- 폴링 상태(성공/오류), 팀 수 확인

단축키: `P` 패널 토글, `←/→` 화면 이동, `Space` 일시정지/재생.
패널 안에 관리자 페이지·현황 화면으로 가는 링크도 있습니다.

## 관리자 페이지 (`admin.html`)

진행자가 결과를 검토하고 게시하는 페이지입니다. 정적 호스팅(GitHub Pages)에는
서버가 없으므로, 이 페이지는 브라우저에서 **GitHub API를 직접 호출**해
`published.json`을 커밋하는 방식으로 동작합니다.

1. 저장소에 대한 쓰기 권한이 있는 GitHub Personal Access Token을 준비합니다
   (fine-grained 토큰이면 이 저장소에 `Contents: Read and write` 권한만 부여).
2. `admin.html` 상단에 토큰을 입력하고 **저장**을 누릅니다. 토큰은 서버로
   전송되지 않고 브라우저 세션 저장소(`sessionStorage`)에만 남으며, 탭을
   닫으면 사라집니다.
3. `results.json`(초안) 기준 예상 순위표와, 현재 게시본 대비 변동
   (▲/▼/NEW)이 표로 보입니다. "결과 JSON 직접 입력" 칸에는 항상 현재
   `results.json` 내용이 채워져 있습니다.
4. **게시하기**를 누르면 확인창 후 `published.json`을 커밋합니다. 성공하면
   바로 아래에 "순위 변동" 리뷰(이전 점수 → 이후 점수, ▲/▼)가 나타나고,
   실시간 화면·현황 화면에는 다음 폴링(최대 15초) 안에 반영됩니다. 동시에
   그 시점의 전체 순위 스냅샷이 `history.json`에 한 건 더 쌓입니다
   (아래 "게시 히스토리" 참고).

### `results.json`을 안 거치고 바로 붙여넣기

저장소에 아직 커밋되지 않은 결과(채점 에이전트가 슬랙/터미널 등으로만 준
JSON)도 그대로 붙여넣어 미리보기·게시할 수 있습니다.

1. "결과 JSON 직접 입력" 칸의 내용을 지우고 원하는 JSON 전체를 붙여넣습니다
   (스키마는 `results.json`과 동일 — 아래 참고).
2. **이 내용 사용**을 누르면 형식을 검사하고, 통과하면 그 내용으로 아래
   미리보기 표(예상 순위·변동 배지)가 즉시 갱신됩니다. JSON이 깨져 있으면
   구체적인 오류 메시지가 뜨고 표는 바뀌지 않습니다.
3. 이후 **게시하기**를 누르면 저장소의 `results.json`이 아니라 지금
   붙여넣은 내용이 `published.json`에 커밋됩니다.
4. **results.json 다시 불러오기**를 누르면 저장소의 최신 `results.json`
   내용으로 칸이 다시 채워지고, 붙여넣은 내용은 버려집니다.

### 게시 히스토리 (`history.json`)

게시할 때마다 그 시점의 전체 순위 스냅샷(시각, 이벤트 정보, 팀별 순위·점수)이
`history.json`의 `entries` 배열에 **추가**됩니다(기존 기록은 지우지 않고
계속 쌓입니다). 관리자 페이지 맨 아래 "게시 히스토리" 표에서 최근 게시
목록(시각·팀 수·1~3위)을 볼 수 있습니다. `published.json`을 커밋하는
요청과는 별도의 커밋으로 저장되며, 히스토리 저장에 실패해도(예: 네트워크
오류) 이미 끝난 게시 자체는 취소되지 않고 화면에 별도로 오류만 표시됩니다.

`admin.js` 상단의 `REPO_OWNER` / `REPO_NAME` / `BRANCH` 상수는 GitHub Pages
배포 워크플로우가 빌드하는 브랜치와 일치해야 합니다. 지금은 저장소가 처음에
비어 있어서 이 브랜치가 기본 브랜치가 됐기 때문에 `BRANCH`도 그 브랜치명으로
맞춰뒀습니다 — 나중에 `main`으로 정리되면 `admin.js`와
`.github/workflows/deploy-pages.yml`의 브랜치 설정을 함께 업데이트하세요.

이 페이지는 접근 자체를 막아두지 않았습니다(정적 사이트라 로그인 화면을 만들
수 없음). 실제 보안은 GitHub API가 담당합니다 — 쓰기 권한이 없는 토큰으로는
게시 요청 자체가 거부됩니다. `admin.html` 링크는 참가자에게 공유하지 마세요.

## 현황 화면 (`status.html`)

빔프로젝터의 순환 연출 없이, 게시된 전체 순위를 표 하나로 항상 볼 수 있는
화면입니다. 필요할 때 아무 때나 접속해서 확인하는 용도로, `published.json`을
15초마다 자동 갱신합니다.

## 발표 순서 추첨 (`draw.html`)

16팀의 발표 순서를 정하는 연출용 화면입니다. `results.json`에서 팀 목록(팀명·
에이전트명)만 읽어오고 점수는 사용하지 않습니다 — 점수 공개 전에 미리 써도
됩니다.

1. `draw.html`을 열면 우주선 16대가 지구 옆에 대기한 인트로 화면이 뜹니다.
2. **🚀 추첨 시작**을 누르면 각 우주선이 **서로 다른 무작위 시각**에 지구를
   출발합니다(동시 출발 아님) — 그래서 지금 화면에 보이는 위치만으로는
   "누가 잘 가고 있는지" 짐작할 수 없습니다. 출발한 우주선은 각자
   무작위 시간만큼 날다가 추진력을 잃고 멈추는데, 실제로 날아간 시간만큼
   지구에서 멀어진 자리에 그대로 정지합니다. 최종적으로 **지구에 가장
   가까이 멈춘 팀이 1번(첫 발표)**, 가장 멀리 멈춘 팀이 마지막 발표가
   됩니다.
3. 우주선이 멈출 때마다 오른쪽 "발표 순서" 패널에 팀 이름만 추가됩니다
   (번호는 아직 안 보임) — **16팀이 모두 멈추기 전까지는 누가 1등이고
   꼴찌인지 진행자를 포함해 아무도 알 수 없습니다.** 다 멈춘 뒤에야
   "🎉 추첨 완료!" 화면과 함께 1번부터 16번까지 전체 순서가 한 번에
   공개됩니다. **순서 복사**로 클립보드에 텍스트로 복사하거나, 화면을
   캡처해 두세요.
4. 다시 뽑아야 하면 **🔄 다시 추첨**(확인창 있음)으로 새로 진행할 수 있습니다.

순서를 결정하는 실제 난수는 우주선마다 "출발 지연 시각"(0~10초)과
"비행 시간"(4~18초)을 각각 무작위로 부여하는 것이고, 최종적으로 비행
시간이 짧은 순서대로 발표 번호가 매겨지므로 16개 순서의 모든 경우가
동일한 확률입니다. 출발 시각까지 무작위라서 화면만 보고 최종 순서를
예측하기 어렵습니다. 결과는 페이지를 새로고침하면 사라집니다(별도로
저장하지 않는 연출용 화면) — 필요하면 3번의 복사/캡처로 기록해두세요.

## 발표 순서 추첨 (`gacha.html`) — 캡슐 뽑기 버전

같은 목적(16팀 발표 순서 결정)을 다른 연출로 보여주는 화면입니다. 우주선
버전과 달리 여기는 **뽑는 즉시 번호가 공개**되는, 실제 뽑기 기계에 가까운
방식입니다. `draw.html`과 마찬가지로 `results.json`에서 팀 목록만 읽어옵니다.

1. `gacha.html`을 열면 16개의 캡슐이 유리돔 안에서 둥둥 떠 있습니다.
2. **🎰 캡슐 뽑기**를 누를 때마다 무작위 캡슐 하나가 돔에서 사라지고,
   기계 앞 트레이에 캡슐이 떨어져 갈라지면서 안에 든 팀 이름이 드러납니다.
   **처음 뽑힌 팀이 1번**, 이후 뽑히는 순서대로 2, 3, … 번이 매겨지고
   오른쪽 "뽑힌 순서" 패널에 즉시 번호와 함께 쌓입니다(우주선 버전과 달리
   번호를 숨기지 않습니다).
3. 16개를 모두 뽑으면 "🎉 뽑기 완료!" 화면에 전체 순서가 정리되어 나타납니다.
   **순서 복사**로 클립보드에 복사하거나 화면을 캡처해 두세요.
4. 다시 뽑아야 하면 **🔄 다시 뽑기**(확인창 있음)로 돔을 다시 채우고
   새로 진행할 수 있습니다.

한 번 뽑힌 캡슐은 다시 뽑히지 않도록 뽑을 때마다 남은 캡슐 목록에서
제거하는 방식(비복원추출)이라, 16번의 뽑기가 끝나면 1~16번이 정확히
한 번씩만 나옵니다. 애니메이션 도중에는 버튼이 잠겨서 연타로 두 번
연속 뽑히는 것을 막습니다. 이 화면도 결과를 저장하지 않으니 복사/캡처로
기록해두세요.

## 로컬 미리보기

정적 파일이므로 아무 정적 서버로 열면 됩니다.

```bash
cd leaderboard
python3 -m http.server 8080
# http://localhost:8080 접속
```

## 배포

`.github/workflows/deploy-pages.yml` 워크플로우가 `leaderboard/` 폴더 변경을 감지해
GitHub Pages로 자동 배포합니다. 저장소 Settings → Pages에서 Source를
**GitHub Actions**로 설정해야 합니다.
